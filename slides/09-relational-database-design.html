Core relationships and cardinality

users1:Nsubjectsuser_id
subjects1:Ntopicscomposite owner reference
users1:Nstudy_plansuser_id
study_plans1:Nstudy_plan_itemscomposite owner reference
topics1:Nstudy_plan_itemsitem topic_id is 0..1, nullable
users1:Nstudy_sessionsuser_id
subjects1:Nstudy_sessionscomposite owner reference
topics1:Nstudy_sessionssession topic_id 0..1, nullable

Composite ownership: topics (user_id, subject_id) references subjects (user_id, id). Plan items use (user_id, plan_id) for the owning plan and optional (user_id, topic_id) for the topic. Sessions use (user_id, subject_id) for subject ownership and optional (topic_id, subject_id) to keep the topic aligned with its subject.

Six core tables from the 18-table design; supporting areas include authentication, check-ins, and progression
